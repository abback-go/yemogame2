## 주인공 스프라이트시트 — 규격 (유저 확정 2026-08-08)

| 항목 | 값 |
|---|---|
| 시트 전체 | **648 × 696** |
| 프레임(셀) | **108 × 116** |
| 격자 | **6열 × 6행** |
| 캐릭터 실제 높이 | **83px** (실측) — 유저 전달값 "약 96px"은 창끝 포함 눈대중이었다 |
| 캐릭터 실제 폭 | 몸통 코어 **21~25px** — 유저 전달값 "약 46px"은 창 자루 포함값 |
| **피벗** | **x=35, y=111** — 유저 전달값 y=110은 1px 어긋난다(아래 「피벗 y」) |

```js
const SHEET = { frameWidth: 108, frameHeight: 116, cols: 6, rows: 6,
                pivotX: 35, pivotY: 111 };   // 픽셀 단위, 셀 좌상단 기준
```

**셀이 캐릭터보다 큰 이유** — 남는 공간은 **창과 망토**가 차지한다. 특히 공격 3번 프레임에서
창이 오른쪽으로 길게 뻗어서 셀 폭이 108이 됐다. 그래서 **피벗이 셀 한가운데(54)가 아니라 x=35**다.
캐릭터가 셀 왼쪽으로 치우쳐 있고 오른쪽이 창 여유 공간이다.

> ⚠ **이 피벗을 안 넣으면** 캐릭터가 화면에서 오른쪽으로 밀려 보이고, **좌우 반전할 때 발 위치가 튄다.**

**확대는 정수배만.** 1.5배·2.5배를 쓰면 픽셀 폭이 어떤 줄은 1, 어떤 줄은 2가 되어 도트가 지저분해진다.

| 배율 | 화면 크기 | 캐릭터 높이 |
|---|---|---|
| 2× | 216 × 232 | 192px |
| 3× | 324 × 348 | 288px |
| 4× | 432 × 464 | 384px |

렌더 시 `ctx.imageSmoothingEnabled = false` 필수.

## 행 구성 `[재확정 2026-08-08 · 바운딩박스 실측 + 3배 확대 육안 대조]`

> ⚠ **이 표의 이전 판(5행 = 피격·쓰러짐)은 틀렸다.** 바운딩박스만 보고 추정했다가
> 5행을 「쓰러짐」으로 오독했다. 5·6행을 3배로 확대해 직접 보고 정정했다.

| 행 | 프레임 | 동작 | 실측 근거 |
|---|---|---|---|
| 1 | 6 | **대기(idle)** | 창을 세워 들고 호흡. 6프레임 바운딩박스 거의 동일 |
| 2 | 4 | **달리기(run)** | 앞으로 크게 기운 자세. 5·6열 빈 셀 |
| 3 | 5 | **점프/공중** | 1 웅크림 → 2 상승 → 3 정점 → 4 낙하 → 5 착지. 6열 빈 셀 |
| 4 | 4 | **공격 — 창 찌르기** | 3프레임에서 창이 x103까지 뻗는다(= 셀 폭 108의 이유). 5·6열 빈 셀 |
| 5 | 4 | **대시(dash)** ★정정 | 1 준비 → 2 기울이며 창 뒤로 → **3·4 몸이 완전히 수평인 돌진 자세** |
| 6 | 6 | **무릎 꿇기 → 기상** | 섬 → 숙임 → 완전히 꿇음 → 일어남 → 반쯤 → 섬. 사당(강림점) 연출용 |

**5행이 대시인 결정적 근거** — 3·4프레임의 바운딩박스가

```
c3  26,60-74,94  (49 × 35)      c4  30,62-77,98  (48 × 37)
```

**폭이 높이보다 크고**(49×35 = 눕힌 형상), **바닥선 y110에 닿지 않는다**(y94·y98에서 끝남).
쓰러진 몸은 바닥에 닿아야 한다 — 안 닿으므로 **공중 돌진**이다.

**6행이 피격이 아닌 근거** — **창이 6프레임 내내 수직으로 꽂힌 채 유지**되고 자세가 통제돼 있다.
피격이면 몸이 뒤로 튕기고 창이 흐트러진다. 높이가 96→85→**76**→84→88→97로
내려갔다 되돌아오는 **완결 사이클**이고 전 프레임이 바닥선 y110에 접지한다.

### ⚠ 없는 애니메이션 — 외주 요청 필요

| 필요 | 현재 | 대응 |
|---|---|---|
| **피격(hurt)** | **시트에 없음** | 임시로 기존 프레임 + 코드 연출(틴트·깜빡임). 스프라이트 요청 대상 |
| **창대쉬(공중 8방향)** | 없음 | 체공 3 + 수평 2 + 대각 ↗↘ 각 2 + 수직 ↑↓ 각 2. 좌우 반전만 사용(상하 반전 금지) |
| 벽 슬라이드 | 없음 | 점프행 정점 프레임으로 대용 중 |

## ✅ 해결 — 히트박스 확정 (2026-08-08)

`bodyH: 0.46`은 **캐릭터 없이 맵을 짤 때 넣은 임시값**이 맞았다. 다만 위에 적었던
"캐릭터 실제 높이 96px"은 **창끝을 포함한 눈대중**이었고, 프레임 실측값은 다르다.

| 실측 | 값 | 방법 |
|---|---|---|
| 발 기준선 | 몸 픽셀 마지막 행 **y110** → 발바닥 경계 **y111** | **5행(대시) 2~4프레임을 뺀 전 프레임 공통** |
| 머리 정수리 | 대기 6프레임 전부 **y28** | 폭 ≥9px 연속 런이 처음 나오는 행(위쪽은 창 자루 ≤7px) |
| **서 있는 실높이** | **83px = 0.83u** | 111 − 28 |
| 몸통 코어 폭 | 발목 14px · **몸통 21~25px** · 달리기 보폭 21px | 행별 x-런(창 자루 x47~49 제외) |

> ⚠ **발 기준선의 유일한 예외 = 5행 대시.** c2가 y108, **c3가 y94, c4가 y98**로 떠 있다.
> 피벗 y111로 그대로 찍으면 돌진 프레임에서 캐릭터가 **지면 위 12~17px(0.12~0.17u) 떠 보인다.**
> 돌진 연출로는 자연스러우나 **의도한 것인지 컨트롤러에서 판단할 것** — 접지 대시라면 오프셋 보정이 필요하다.

> ⚠ **「상체 18~20px」은 이전 판의 오측이었다.** 창 자루(x47~49, 전 행 관통하는 폭 3px 런)를
> 몸통 런과 분리하지 않아 생긴 오차다. 분리 후 실측은 **21~25px**(y74·y98에서 25px 최대).

**확정값**

```
bodyW: 0.30u   bodyH: 0.82u        // 1u = 100px @PPU100
```

- `bodyH 0.82` — 실측 0.83에서 1px 여유. **점프비 1.94배**(구 0.46은 3.46배).
- `bodyW 0.30` **유지** — 코어(최대 25px)를 좌우 2~3px씩 감싼다.
  더 넓히면 **3F 히든 니치(폭 0.6u)** 진입이 막힌다.

> ⚠ **피벗 x35는 「코어 중심」이 아니라 「발 중심」이다.** (이전 판의 서술을 정정)
> y110에서 발 런은 x30~39 → 중심 **34.5**. 반면 몸통은 x17~43 → 중심 **약 30**.
> 즉 피벗을 중심으로 놓은 히트박스(x20~50)는 **몸통보다 약 5px 오른쪽으로 치우친다.**
> 접지점 기준으로는 x35가 옳으므로 **피벗은 유지**하되, 0.05u 편차는 `ledgeSnap 0.08u`보다
> 작아 게이팅에 영향이 없다고 판단했다. 히트박스를 좁힐 일이 생기면 이 편차를 먼저 볼 것.
- 머리카락 끝단(y26)·치맛자락(x8)·창(x46~103)은 **제외**.
  **히트박스는 실루엣이 아니라 플레이 감각이 정한다.**

**맵 영향:** 7F 좌측 전망 발코니 하면만 `y1.3 → 1.6`으로 올렸다
(테라스 위 여유 0.80u < 0.82u라 그 아래 **사당5**에 설 수 없었다). 다른 층은 수정 없음.
검증은 **12항목 전부 PASS**(신규 12번 = 「필수 지점 신체 여유」).
상세는 `docs/specs/2026-08-07-temple-training-map.md`의 「개정 v1.2」.

## ⚠ 피벗 y는 110이 아니라 **111**이다

위 표의 `pivotY: 110`은 **1px 어긋난다.** 몸 픽셀의 마지막 행이 y110이므로
"발바닥이 닿는 경계선"은 **y111**이고, 110을 쓰면 스프라이트가 **1px 지면에 잠긴다.**

```js
const SHEET = { frameWidth:108, frameHeight:116, cols:6, rows:6,
                pivotX:35, pivotY:111 };   // Phaser: setOrigin(0.324, 0.957)
```

`proto/index.html`은 **111**을 쓴다. Unity/Phaser로 옮길 때도 111을 쓸 것.
