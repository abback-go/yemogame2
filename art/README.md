## 주인공 스프라이트시트 — 규격 (유저 확정 2026-08-08)

| 항목 | 값 |
|---|---|
| 시트 전체 | **648 × 696** |
| 프레임(셀) | **108 × 116** |
| 격자 | **6열 × 6행** |
| 캐릭터 실제 높이 | 약 **96px** |
| 캐릭터 실제 폭 | 약 **46px** (idle 기준) |
| **피벗** | **x=35, y=110** → `setOrigin(0.324, 0.948)` |

```js
const SHEET = { frameWidth: 108, frameHeight: 116, cols: 6, rows: 6,
                pivotX: 35, pivotY: 110 };   // 픽셀 단위, 셀 좌상단 기준
```

**셀이 캐릭터보다 큰 이유** — 남는 공간은 **창과 망토**가 차지한다. 특히 공격 3번 프레임에서
창이 오른쪽으로 길게 뻗어서 셀 폭이 108이 됐다. 그래서 **피벗이 셀 한가운데(54)가 아니라 x=35**다.
캐릭터가 셀 왼쪽으로 치우쳐 있고 오른쪽이 창 여유 공간이다.

> ⚠ **이 피벗을 안 넣으면** 캐릭터가 화면에서 오른쪽으로 밀려 보이고, **좌우 반전할 때 발 위치가 튄다.**

**확대는 정수배만.** 1.5배·2.5배를 쓰면 픽셀 폭이 어떤 줄은 1, 어떤 줄은 2가 되어 도트가 지저분해진다.

| 배율 | 화면 크기 | 캐릭터 높이 |
|---|---|---|
| 2× | 216 × 232 | 192px |
| 3× | 324 × 348 | 288px |
| 4× | 432 × 464 | 384px |

렌더 시 `ctx.imageSmoothingEnabled = false` 필수.

## ⚠ 미해결 — 스프라이트와 프로토 히트박스가 안 맞는다

`proto/index.html`의 `PHYS`는 이렇게 되어 있다.

```
bodyW: 0.30u   bodyH: 0.46u        // 1u = 100px @PPU100
```

즉 **히트박스는 30 × 46 px**인데 **스프라이트 캐릭터는 46 × 96 px**다. **키가 2배 넘게 차이난다.**

**어느 쪽이 맞는지 정해야 하고, 어느 쪽으로 가든 대가가 있다.**

| 안 | 방법 | 대가 |
|---|---|---|
| **ⓐ 스프라이트에 맞춘다** | `bodyH` 0.46 → **0.96**, `bodyW` 0.30 → 0.46 | **맵 검증 11항목을 다시 돌려야 한다.** 천장·터널·갭 여유가 전부 바뀐다 |
| ⓑ PPU를 바꾼다 | 96px = 0.46u가 되게 **PPU ≈ 209** | 어중간한 수라 타일·UI가 전부 비정수가 된다. **비추천** |

**ⓐ가 맞을 가능성이 높다.** 근거: 현재 점프 높이 `1.592u` ÷ `bodyH 0.46u` = **자기 키의 3.5배**를 뛴다.
할로우 나이트는 **1.5배** 정도다. `bodyH`를 0.96으로 고치면 **1.66배**가 되어 정상 범위에 들어온다.
→ **`bodyH: 0.46`은 캐릭터 없이 맵을 짤 때 넣은 임시값일 가능성이 크다.**

⇒ **다음 세션 첫 작업: `bodyH`를 확정하고 `node proto/verify-map.mjs`를 다시 돌린다.**
   FAIL이 나오면 맵 수정이 필요하고, 그건 **스프라이트를 더 그리기 전에** 해야 한다.
