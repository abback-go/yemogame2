당신은 Unity MCP를 사용해 2D 픽셀아트 메트로베니아의 「이동 수직 슬라이스」를 만듭니다.
원본은 이미 완성되어 검증을 통과한 웹 프로토타입이고, 당신의 일은 그것을 Unity로
**정확히 재현**하는 것입니다. 새로 설계하지 마세요.

## 먼저 할 일

첨부된 `unity-handoff.zip`을 풀고 `docs/unity/README.md`를 **끝까지** 읽으세요.
그 문서가 구현 명세의 정본입니다. 다 읽기 전에는 코드를 쓰지 마세요.

읽는 순서:
  1. docs/unity/README.md          ← 구현 명세 (정본)
  2. docs/unity/tuning.json        ← 물리·컨트롤러·이펙트·애니 전 수치
  3. docs/unity/temple-map.json    ← 7층 맵 데이터
  4. docs/unity/RENDERING.md       ← 맵·이펙트 렌더링 레시피 (에셋 없이 같은 룩)
  5. docs/game-design.md           ← 설계 원칙. README §1.3 「읽는 법」을 먼저 볼 것

## 절대 규칙 5가지

1. **tuning.json의 PHYS 값을 바꾸지 마세요.** 이 수치들이 맵 게이팅 전체를 결정합니다.
   감각이 안 맞으면 바꾸지 말고 **먼저 보고**하세요.

2. **Rigidbody2D 기본 물리를 쓰지 마세요.** 커스텀 캐릭터 컨트롤러로 구현합니다.
   원본은 고정 타임스텝 1/120으로 적분합니다. FixedUpdate 기본값으로는 재현되지 않습니다.

3. **도달 수치(REACH)를 하드코딩하지 마세요.** PHYS에서 유도하세요.
   검증 기준값도 마찬가지입니다 — 리터럴을 박으면 검사기가 눈뜬장님이 됩니다.
   (원본에서 이 원칙을 어겨 시퀀스 브레이크 5건이 "12/12 통과"로 새어나간 전례가 있습니다.)

4. **감각 수치를 당신 판단으로 확정하지 마세요.** 체공 시간·돌진 속도·진동 세기·
   이펙트 길이는 인스펙터에 노출하고, 시작값은 문서 값을 쓰고, 판정은 오너에게 넘기세요.

5. **검증을 역검증하세요.** 일부러 값을 망가뜨려 FAIL이 재현되는지 확인하기 전에는
   "통과했습니다"라고 보고하지 마세요. 방법은 README §9.3에 있습니다.

## 진행 방식

README §11의 빌드 순서 12단계를 따르세요. **각 단계의 합격 기준을 통과하기 전에

## 그래픽 — 에셋을 찾지 마세요

맵 그래픽은 **에셋이 아니라 코드**입니다. 타일셋도 배경 이미지도 없고, **필요 없습니다.**
원본은 전부 그라디언트 + 축정렬 사각형 + 단순 다각형으로 그립니다
(외부 텍스처 0장, 블러 0회). **그대로 이식하세요.**

레시피는 `docs/unity/RENDERING.md`에 전부 있습니다 — 팔레트 정확한 값, 지오메트리
타입별 페인트 순서, 배경 4레이어, 갓레이, FX 파티클 대응표까지.

이펙트도 마찬가지입니다. 필요한 텍스처는 **64×64 소프트 원 1장**뿐이고 런타임 생성이 됩니다.
Unity 기본 파티클 시스템은 쓰지 마세요 — 모양이 전용(바늘 속도선·초승달 참격·렌즈 빛줄기)이라
기본 셰이프로 안 나옵니다. 단순 풀 + 절차적 메시로 만드세요.

**타일셋을 사거나 만들자고 제안하지 마세요.** 최종 화풍 확정은 데모 시점의 결정이고,
아트 티어가 총 작업시간을 700h ↔ 2,300h로 흔들어서 되돌릴 수 없습니다.
지금은 "주스를 입힌 읽히는 도형"이 맞습니다 (game-design.md §9.1).
