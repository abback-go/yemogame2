### 1.3 `game-design.md` 읽는 법 — 소재만 치환하면 된다

> ⚠ 제목이 「마법학교 메트로베니아」이고 본문이 **마법·학교·속성**으로 쓰여 있지만
> **폐기된 문서가 아니다.** 소재가 **마법 → 신성력 / 학교 → 신전**으로 바뀌었을 뿐
> **루프·시스템·설계 원칙은 그대로 이관된다.** 임의로 무시하거나 삭제하지 마라.

**치환 규칙**

```
마법        →  신성력 / 창술
마법학교    →  신전
교수        →  사제
속성        →  (신전 노선에서 재정의 예정 — 미확정)
원석        →  (재정의 예정 — 미확정)
```

**소재와 무관하게 그대로 유효한 조항** — Unity AI도 지켜야 한다:

| 절 | 내용 |
|---|---|
| **장르 원칙** (문서 최상단) | **메트로베니아다.** 탐험·길찾기·모험이 중심이고 **전투는 요소 중 하나**다. 설계가 전투로 기울면 되돌린다 |
| **§6.9 게임필 체크리스트** | 입력 버퍼 · 코요테 · 캔슬 창 · 짧은 선딜 · 착지/피격 경직 최소화 |
| **§4.3 안티패턴** · **§10 카피 가드레일** | 전 기획 적용 |
| **§12 메트로베니아 설계 체크리스트** (14조) | 레벨을 손대면 통과시켜야 하는 조항 |
| §7.5 「정보는 주고, 길은 안 준다」 | 유도 원칙 |

**§6.9에서 Unity AI가 특히 지킬 두 줄:**

> **「이동 속도는 어떤 성장 요소로도 변하지 않는다」** — 손맛 고정.
> 성장으로 `runSpeed`·`dashSpeed`를 올리는 설계를 제안하지 마라. 도달 게이팅이 전부 무너진다.
>
> **「이 영역은 개발자 본인의 손 튜닝이 최우선 — AI가 대신 못 하는 유일한 영역」**
> 감각 수치를 AI 판단으로 확정하지 마라. **인스펙터에 노출하고 오너에게 넘겨라.**

**§12에서 특히 걸리는 조항** (레벨·시스템을 건드릴 때):

- **#5 하드코드 금지** — 맵이 이미 데이터(`temple-map.json`)다. **이벤트·배치도 같은 규율로.**

- **#9 숨긴 것은 두 종류로 구분** — ①능력 없이 신중한 플레이어가 찾는 것 ②능력을 얻고 되돌아오는 것
- **#12 숏컷** — 패스트트래블과 다르다. **숏컷이 먼저** 와야 한다

**⚠ §9.1의 「지금 잠근 치수」는 이 프로토타입이 갱신했다**

`game-design.md` §9.1에 `카메라 뷰 640×360 · 캐릭터 높이 54 월드단위`라고 적혀 있는데,

**절대 수치는 `tuning.json`이 정본이다.** §9.1의 숫자는 참고로만 읽어라.

## 2. 좌표계 · 단위 — 제일 먼저 맞출 것

```
1u = 100px @PPU100 = Unity 월드 1유닛
원점 = 좌하단, y는 위로 증가   (Unity 기본과 동일)
rect: [x, y, w, h]  →  UnityEngine.Rect(x, y, w, h)  1:1
```

- **스프라이트 Pixels Per Unit = 100**으로 설정한다. 이걸 틀리면 모든 수치가 어긋난다.
- 층은 `yOff`만큼 위로 쌓인다. `월드 y = 층 로컬 y + yOff`.
  Unity에서는 **층별 부모 GameObject를 `yOff`에 놓고 자식은 로컬 좌표**로 배치하면 그대로 맞는다.
- 맵 데이터에 이미 `bbox`·`spawnW`(월드 좌표 스폰)가 계산돼 있다.

## 3. 물리 — `tuning.json`의 `PHYS`가 정본

### 3.1 절대 규칙

> **`PHYS` 값을 바꾸지 마라.** 이 수치들이 맵 게이팅 전체를 결정한다.
> 하나라도 바꾸면 「이 발판은 창대쉬 없이 못 간다」 같은 설계가 전부 무효가 된다.
> 감각이 안 맞으면 **먼저 보고하고 승인을 받아라.**

```jsonc
gravity 26.0      runSpeed 3.92     airControl 0.90
jumpV 9.10        airJumpV 8.20     dashSpeed 7.80    dashTime 0.16
sdashSpeed 11.00  sdashTime 0.15    sdashHover 0.20
airDecayT 0.12    ledgeSnap 0.08    simDt 1/120
bodyW 0.30        bodyH 0.82
```

### 3.2 `REACH`는 상수가 아니라 **유도값**이다

하드코딩하지 마라. `PHYS`에서 계산해라. 그래야 물리를 튜닝하면 게이팅이 자동 재검증된다.

```
h(v)       = v² / (2·gravity)
jump       = h(jumpV)                       = 1.592
doubleJump = jump + h(airJumpV)             = 2.886
sdash      = sdashSpeed × sdashTime         = 1.650   (실제로는 simDt로 올림)
chainUp    = doubleJump + sdash             = 4.536
dashX      = dashSpeed×dashTime + (airT−dashTime)×runSpeed×airControl = 3.153
GATE_MARGIN = max(0.30, ledgeSnap × 3.5)    = 0.300
```

### 3.3 ⚠ Rigidbody2D 기본 물리 사용 금지

**커스텀 캐릭터 컨트롤러로 구현한다.** 이유:
- 원본이 **고정 타임스텝 `simDt = 1/120`, 최대 8서브스텝**으로 적분한다. `FixedUpdate` 기본값(0.02)으로는 재현이 안 된다.
- 가변 점프(`cutJump 0.45`)·코요테(`coyote 0.10`)·점프버퍼(`jumpBuf 0.12`)는 물리엔진이 아니라 컨트롤러가 관리한다.
- 충돌은 **AABB 스윕 + 축분리 해소**다. `Physics2D` 마찰·바운스가 끼면 수치가 흔들린다.

`Time.fixedDeltaTime = 1/120`으로 두거나, 자체 누산기로 `simDt` 스텝을 돌려라.

## 4. 스프라이트 — `art/temple_maiden_sheet_v3.png`

```
864 × 1924 · 셀 144 × 148 · 6열 × 13행 · 24색 · 반투명 픽셀 0개
```

### 4.1 ⚠ 피벗은 (51, **111**)이다 — JSON의 110은 1px 틀렸다

`temple_maiden_anim.json`과 `WEB_USAGE.md`가 `pivot y=110`이라고 적어놨지만 **실측 결과 틀렸다.**
몸 픽셀의 마지막 행이 y110이고 y111이 빈 행이므로, **발바닥 경계선은 y111**이다.
110을 쓰면 스프라이트가 **1px 지면에 잠긴다.**

Unity Sprite Editor 기준(좌하단 원점, 정규화):
```
Pivot X = 51 / 144 = 0.3542
Pivot Y = (148 − 111) / 148 = 0.2500
```

**"캐릭터 높이 약 96px"도 창끝 포함 눈대중이다.** 실측 **83px** (정수리 y28 → 발 y111).
히트박스 `bodyH 0.82`는 이 83px에서 나온 값이다.

### 4.2 행 구성 (인덱스 = row × 6 + col, 빈 셀도 번호를 차지)

| row | 이름 | 인덱스 | 프레임 | fps | loop |
|---|---|---|---|---|---|
| 0 | idle | 0–5 | 6 | 8 | ○ |
| 1 | walk | 6–9 | 4 | 10 | ○ |
| 2 | jump | 12–16 | 5 | — | × (§4.3) |
| 3 | attack | 18–21 | 4 | 16 | × |
| 4 | dash | 24–27 | 4 | 18 | × |
| 5 | hurt | 30–35 | 6 | 10 | × |
| 6 | **run (기본 이동)** | 36–38 | 3 | **유도** | ○ |
| 7 | charge (창대쉬 체공) | 42–44 | 3 | 14 | × |
| 8 | sdash_right → | 48–49 | 2 | 20 | × |
| 9 | sdash_upright ↗ | 54–55 | 2 | 20 | × |
| 10 | sdash_downright ↘ | 60–61 | 2 | 20 | × |
| 11 | sdash_up ↑ | 66–67 | 2 | 20 | × |
| 12 | sdash_down ↓ | 72–73 | 2 | 20 | × |

- **캐릭터는 오른쪽을 향한다.** 왼쪽은 **X축 반전**으로 만든다.
- **8방향 = 5행 + 좌우 반전.** `upright` 반전 = ↖, `downright` 반전 = ↙.
- **상하 반전은 절대 쓰지 마라** — 사람이 거꾸로 매달린 그림이 된다. ↑·↓는 전용 행이 있다.

### 4.3 점프는 프레임 순차 재생이 아니라 **`vy`에 매핑**한다

```
vy < −4  → 인덱스 14 (상승)
vy <  1  → 인덱스 15 (정점)
그 외     → 인덱스 16 (낙하)
```

### 4.4 달리기 fps는 **하드코딩하지 말고 유도**한다

walk 애니를 그대로 쓰면 **캐릭터가 다리보다 1.87배 빠르게 미끄러진다.** 그게 원본의 "밋밋함"이었다.

```
strideU = 0.784u   (실측: 3프레임 사이클 = 1 스트라이드)
fps = runSpeed / strideU × frames = 3.92 / 0.784 × 3 = 15
```

이렇게 두면 나중에 `runSpeed`를 바꿔도 발 미끄러짐이 자동으로 따라온다.

### 4.5 알아둘 것 — 프레임이 바닥선에 안 닿는 경우

- `dash` c3·c4 (인덱스 26·27) 는 y94·y98에서 끝난다 = **공중 자세**. 지상 대시에 쓰면 12~17px 떠 보인다.
- `run` c3 (인덱스 38) 도 y93 = 달리기의 체공 구간. **정상이다.**
- `sdash_down`은 피벗보다 **아래로 31px** 뻗는다(y142까지). 셀 하단을 잘라내면 창끝이 잘린다.
- `charge` 3프레임에서 캐릭터가 눈에 띄게 작아진다(응축 연출). **히트박스는 안 변한다** — 판정 시비 소지가 있다.

### 4.6 Unity 임포트 설정

```
Texture Type      Sprite (2D and UI)
Sprite Mode       Multiple  →  Grid By Cell Size 144×148
Pixels Per Unit   100
Filter Mode       Point (no filter)      ← 필수
Compression       None                   ← 필수 (24색이 뭉개진다)
Max Size          2048 이상
Wrap Mode         Clamp
```

## 5. 캐릭터 컨트롤러 — 구현 명세

### 5.1 상태와 입력

| 입력 | 동작 |
|---|---|
| ←→ / A D | 이동 (**기본이 달리기**) |
| Space / Z | 점프 (누르는 시간에 비례 · 공중 재입력 = 이단강림 · 벽에서 = 벽점프) |
| ↓ + 점프 | 원웨이 판 통과 |
| Shift / X | 대시 |
| **C / V** | **창대쉬** (대시와 별개 입력) |
| J | 공격 |
| ↑ / W | 문 통과 |

### 5.2 `CTRL` 값 (`tuning.json`)

```jsonc
accelGround 42   accelAir 26    fricGround 46   fricAir 4     maxFall 22
coyote 0.10      jumpBuf 0.12   cutJump 0.45
dashCool 0.34    sdashCool 0.06
wallSlideV 3.2   wallJumpPush 1.0   wallJumpLock 0.13
camLead 0.9      camUp 0.5      dashFreezeY false
```

### 5.3 ★ 창대쉬 (시그니처 이동기)

레퍼런스는 **오리와 도깨비불의 충전 점프**다.

```
1) 공중에서 C 입력  →  sdashHover 0.20초 동안 그 자리에 정지
                       중력 0, 수평속도 0. 창을 모으며 응축한다.
2) 8방향 중 하나로  →  sdashTime 0.15초 동안 sdashSpeed 11.0 u/s로 돌진
3) 종료 시 상승분 소멸 → airDecayT 0.12초에 걸쳐 수평속도가 상한으로 감쇠
```

- **충전은 1회.** **접지** 또는 **`wallJump:true`로 지정된 벽에 접촉**할 때만 회복된다.
- ⚠ **아무 벽에서나 회복시키면 안 된다.** 경계벽에 붙어 「충전 → 창대쉬 → 다시 붙기」로
  **무한 상승**이 되어 층 전체가 스킵된다. 이건 실제로 발생했던 버그다.
  검증 항목 「벽점프 슈트가 경계벽이 아님」이 이걸 잡는다.
- 창을 **던지지 않는다.** 창은 끝까지 손에 있다.

### 5.4 공중 수평 감쇠 (하드 클램프 금지)

대시·창대쉬 후 수평속도가 상한(`runSpeed × airControl`)을 넘으면
**즉시 자르지 말고 `airDecayT 0.12`초에 걸쳐 선형 감쇠**시킨다.
즉시 절단하면 대시 관성이 뚝 끊겨 감각이 죽는다. 게이팅은 도달 포락선이 보장하므로 관성을 살려도 안전하다.

단, **벽점프 반동(`wallJumpLock`) 구간·대시 중·창대쉬 중**은 감쇠에서 제외한다.

### 5.5 착지 감지 — 허용오차로 판정하지 마라

원본에서 **착지 이벤트의 45%가 유실되던 버그**가 있었다. 원인은 접지 판정의 0.03u 허용오차가
실제 착지 **직전** 스텝에서 먼저 켜져서 「직전에 안 닿았다」가 성립하지 않은 것이다.

**수직 충돌이 실제로 해소됐는가(`이번 스텝 해소` && `직전 스텝 미해소`)로 판정해라.**
허용오차가 개입하지 않는 결정론적 신호다.

## 6. 카메라

```
배율     PLAY.scale = 2   →   1u = 200 화면픽셀
시야     1920×1080 → 9.6 × 5.4u      1600×900 → 8.0 × 4.5u (설계 기준)
추적     목표 = 플레이어 + (바라보는 방향 × camLead 0.9, camUp 0.5)
클램프   층 경계 안으로 제한. 층이 시야보다 작으면 중앙 고정
스냅     카메라 위치를 디바이스 픽셀 격자에 반올림  ← 도트 떨림 방지
```

- **정수 배율만 쓴다.** 1.5배 같은 소수 배율은 픽셀 폭이 불균등해져 도트가 지저분해진다.
- Unity에서는 **Orthographic Size = 화면세로픽셀 / (2 × PPU × scale)**.
  1080p·2배 → `1080 / (2 × 100 × 2) = 2.7`.
- **Pixel Perfect Camera** 컴포넌트를 쓰되 Upscale RT는 끄고 `Pixel Snapping`을 켜라.

### 6.1 이 배율이 맵에 준 제약 — 반드시 지킬 것

```
최대 상승 체인 4.536u  ≈  세로 시야 4.5u (900p)
→ 풀 체인 한 번이 화면을 통째로 먹는다 = 착지 지점이 안 보이는 맹목 점프
```

그래서 맵이 이 규칙에 맞춰 재조정돼 있다. **Unity에서 맵을 손대면 이 규칙을 다시 검사해라.**

- **연속 상승 ≤ 4.34u** — 그 이상 오르려면 중간 착지 지점이 있어야 한다
- **게이트는 출발 시점 시야 안** — 출발 발판에서 목표까지 `dx ≤ 3.55u && dy ≤ 3.55u`

두 기준 모두 `배율`·`기준해상도`·`REACH`에서 **유도**한다. 상수로 박지 마라.

## 7. 맵 데이터 — `temple-map.json`

### 7.1 구조

```jsonc
{ schema:"temple-map/1.1", units:"u", ppu:100, origin:"bottom-left", yUp:true,
  floors:[ {
    n:1, id:"plaza", name:"입구 대광장", yOff:0, w:34, h:6,
    geo:[ {id:"plaza_floor", t:"solid", rect:[0,0,34,1], stand:true, label:"대광장 바닥"} ],
    hazards:[], checkpoints:[], portals:[], targets:[], collectibles:[], spawnW:[x,y]
  } ] }
```

### 7.2 `geo[].t` — 4종 (전 층 합계 74개)

| t | 개수 | Unity 구현 |
|---|---|---|
| `solid` | 32 | `BoxCollider2D`. 사방 충돌 |
| `wall` | 28 | `BoxCollider2D`. 벽 판정 전용(위에 못 섬) |
| `oneway` | 8 | `PlatformEffector2D` 또는 자체 구현. **↓+점프로 통과** |
| `deco` | 6 | **콜라이더 없음.** 시각용 |

### 7.3 주요 플래그

| 필드 | 의미 |
|---|---|
| `stand: true` | 위에 설 수 있다 |
| `stand: false` | 못 선다. `cap:"finial"`이면 **미끄러진다**(첨탑 꼭대기) |
| `gate:"sdash"` | **창대쉬 없이는 못 넘는 구간.** 설계의 핵심 |
| `wallJump: true` | 이 벽에서만 벽점프·창대쉬 충전이 성립 |
| `dropThrough` | 원웨이 통과 허용 |

### 7.4 ⚠ 창 꽂기 관련 필드는 **비활성 상태**다

`spearFaces`·`spearPlan`은 전부 빈 배열이고 `MAP.spear.enabled = false`다.
「창을 던져 벽에 꽂고 밟는」 이동기는 **창대쉬로 대체되어 폐기**됐다.
데이터 구조만 남아 있으니 **구현하지 마라.**

## 8. FX (타격감) — `tuning.json`의 `FX` 72개 값

원본과 똑같이 만들 필요는 없다. **원칙만 지켜라.**

### 8.1 절대 규칙

> **이펙트가 물리에 되먹임되면 안 된다.**
> 원본은 이펙트를 전부 꺼도 이동 실측값이 **한 글자도 안 변한다.**
> Unity에서도 이펙트 on/off 양쪽에서 §9 검증이 통과해야 한다.

- 물리 시간축(고정 스텝)과 이펙트 시간축을 **분리**한다.
- **히트스톱·슬로우를 물리 `dt`에 걸지 마라.** 원본이 이 때문에 히트스톱을 포기했다.
  필요하면 **렌더 전용 프리즈**(물리는 계속 돌고 그리기만 정지)로 구현해라.

### 8.2 이펙트별 (레퍼런스와 지속시간)

| 동작 | 그림 | 지속 |
|---|---|---|
| **대시** | 실크송식 **순백 속도선 9가닥**이 진행 **반대**로 부챗살. 잔상 아님 | 0.13s |
| **창대쉬 충전** | 금색 **발광 도넛**이 수축하며 굵어짐 + 수렴 알갱이 + **8방향 조준 지향선** | 0.20s |
| **창대쉬 발사** | 양 끝 뾰족한 **렌즈형 금색 빛줄기** + 불똥 + 충격파 링 | 0.19s |
| **참격** | 초승달 아크. 가운데 굵고 양끝 뾰족 | 0.10s |
| 착지 | 낙하속도 비례 먼지 퍼프 | — |
| 벽 박차기 | 벽면 부채꼴 먼지 + 반대 방향 속도선 | — |
| 달리기 | 발밑 작은 먼지 | — |

- **신성력은 금색이다.** 파랑·보라를 쓰면 캐릭터 팔레트와 따로 논다.
- **조준 지향선은 연출이 아니라 정보다.** 없으면 어디로 나갈지 몰라 조작이 답답해진다.
  길이 1.20u — 더 길면 2배 시야를 벗어난다.
- **빛과 먼지를 다르게 그린다.** 빛은 원형 글로우, 먼지는 각진 블록(도트 감성).

### 8.3 참격 아크는 **스프라이트 실측에 맞춘다**

눈대중으로 놓으면 호가 창에서 떨어져 「내가 벤 것」이 아니라 「옆에서 뭔가 지나간 것」으로 읽힌다.

```
attack 4프레임 창끝 (셀 좌표): f0(91,2) f1(110,25) f2(119,48) f3(105,95)
회전 중심 = 셀 (60,58) = 어깨 = 피벗 기준 (+0.09u, +0.53u)
반경 0.72u · 스팬 1.752rad(100.4°) · 중심각 +0.188rad
발화 지연 0.055s  ← 타격 프레임 f1~f2에 맞춤. 즉시 그리면 창이 아직 머리 위다
```

### 8.4 화면 진동은 **아주 약하게 시작한다**

```
최대 진폭 = 화면 높이의 0.5%   (1080p에서 5.4px)
효과별 배율: 착지 0.55 · 창대쉬 발사 0.55 · 대시 0.20 · 벽차기 0.16 · 이단강림 0.10
달리기·점프·벽슬라이드 = 0
```

실측 피크는 0.7~1.0px다. **의도적으로 매우 약하다.**
프로젝트 오너가 이전에 "화면 흔들림 줄여줘, 어지러워"라고 명시한 전례가 있다.
**약한 쪽에서 시작해 요청이 오면 올린다.** 반대로 하지 마라.

카메라 위치를 직접 흔들지 말고 **렌더 오프셋**으로 처리해라(카메라를 흔들면 좌표 역산이 깨진다).

## 9. 검증 — 이식 성공 판정

원본은 게임 안에서 도는 **19항목 자동 검증**이 있고 전부 통과한다.
Unity에서도 **같은 검사를 EditMode/PlayMode 테스트로 옮겨라.** 이게 이식 품질의 유일한 객관 지표다.

### 9.1 반드시 옮길 핵심 6항목

| 항목 | 무엇을 막는가 |
|---|---|
| **이동기 실측 ≤ 유도 도달** | 컨트롤러가 물리 계약을 벗어남 |
| **게이트 = 창대쉬 없이 불가 / 있으면 가능** (양면) | 게이팅이 실제로 성립하는가 |
| **벽점프 슈트가 경계벽이 아님** | 무한 상승으로 층 스킵 |
| **층 경계 밖으로 나갈 수 없음** (전 층 실주행) | 맵 이탈 |
| **게이트가 출발 시점 시야 안** | 맹목 점프 |
| **연속 상승 ≤ 4.34u** | 맹목 점프 |

### 9.2 ★ 검사에 리터럴을 박지 마라 (개발 원칙 5)

기준값은 **`PHYS`·맵 데이터·배율에서 유도**해야 한다.
원본에서 이 원칙을 어겨 **시퀀스 브레이크 5건이 12/12 PASS로 통과한 전례**가 있다.

### 9.3 ★ 검사기를 역검증해라 — 안 그러면 통과에 의미가 없다

**일부러 망가뜨려서 FAIL이 재현되는지 확인한다.** 원본에서 실제로 돌린 것:

| 변형 | 기대 |
|---|---|
| 배율을 **완화**(2→1) | **PASS 유지** ← 완화 방향은 통과해야 정상 |
| 배율을 강화(2→3) | FAIL |
| `sdashSpeed` → 0 | 다수 FAIL (게이팅이 창대쉬에 실제 의존) |
| `ledgeSnap` 0.08 → 0.90 | FAIL (`GATE_MARGIN` 유도 확인) |
| `bodyH` 0.82 → 1.60 | FAIL (신체·천장 여유) |
| 1F 우측 벽 제거 | FAIL (경계 이탈) |

원본에서 `ledgeSnap`을 0.90으로 바꿔도 **전 항목 PASS**였던 시기가 있다. 그게 검사기가 눈뜬장님이었다는 증거다.

### 9.4 검증 하네스 자체도 틀린다

원본에서 실제로 있었던 일:
- 측정 하네스가 점프 키를 안 눌러 **모든 비행이 45% 높이로 측정**됐다 → 계약 검사가 통째로 공허했다
- 검증자가 **게임 루프 밖에서** 물리 함수를 직접 호출해 100% 오답을 냈다
- 파티클을 **순증가로 세다가** 소멸 중인 이전 파티클에 새 스폰이 가려졌다

**극단값을 주입해 수치가 반응하는지** 확인하고 나서 하네스를 믿어라.

## 10. ⚠ 제공되지 않는 것 — 이걸 모르고 시작하면 막힌다

### 10.1 맵 그래픽은 **에셋이 아니라 코드다** — 그대로 이식한다 `[오너 확정]`

프로토타입의 맵 비주얼(대리석 기둥·구름 하늘·갓레이·시차 배경)은 **전부 코드로 그린 도형**이다.
타일셋도 배경 이미지도 없다. **하지만 그게 문제가 아니다 — 그대로 옮기면 된다.**

```
외부 텍스처   0장   (FX의 소프트 원 1장만 필요하고, 그것도 런타임 생성 가능)
블러          0회
쓰인 기법     선형 그라디언트 21 · 방사형 12 · 가산 합성 18 · 단순 곡선 15
```

전부 **축정렬 사각형 + 그라디언트 + 단순 다각형**이라 Unity 셰이더 몇 개로 같은 그림이 나온다.

> **→ 구현 레시피는 [`RENDERING.md`](RENDERING.md)에 전부 있다.**
> 팔레트 정확한 값 · 지오메트리 타입별 페인트 순서 · 배경 4레이어 · 갓레이 · FX 파티클 대응표.

**이게 프로젝트 방침이기도 하다** — `game-design.md` §9.1:

> *"최종 화풍을 지금 정하지 않는다. 게임을 먼저 완성하고, 아트는 딱 한 번만 입힌다."*
> *"재미 검증은 **주스를 입힌 읽히는 도형** 상태에서 한다 — 주스 코드는 최종 아트에도 그대로 산다."*

**최종 픽셀아트 화풍 확정은 데모 시점(§9.4 리트머스)의 결정이다. 지금 타일셋을 사지 마라.**
아트 티어가 총 아트 시간을 700h ↔ 2,300h로 흔들기 때문에 되돌릴 수 없는 결정이다.

### 10.2 없는 것들

| | 상태 |
|---|---|
| **적 · 전투** | 없다. 이 수련장은 **이동 검증 전용**이다 |
| **오디오** | 효과음·BGM 하나도 없다 |
| **UI · HUD** | 디버그 오버레이뿐. 체력·자원 UI 없음 |
| **피격 · 사망 연출** | `hurt` 스프라이트는 있으나 연출 미구현 |
| **진짜 진행 게이팅** | `gate:"sdash"`는 "이 테크 없이는 못 넘는 구간"이지 **"능력을 얻어야 열리는 문"이 아니다.** 성물=능력=열쇠 축은 아직 설계되지 않았다 |

### 10.3 오너 승인이 필요한 미결 사항

Unity AI가 **임의로 결정하면 안 되는** 것들이다. 마주치면 **보고하고 멈춰라.**

1. **창대 도약(vault) 폐지** — 창대쉬가 앞질러서 폐기됐지만 원래 시그니처의 일부였다. 되살릴지 미정
2. **부유 대시 `dashFreezeY`** — 현재 `false`. `true`면 도달 4.18u / `false`면 5.33u. 순수 감각 판단
3. **창대쉬 충전 중 시각/충돌 괴리** — 캐릭터가 작아지는데 히트박스는 그대로
4. **진동 세기** — 매우 약하게 잡혀 있다

### 10.4 알려진 구조적 구멍

**`GATE_MARGIN`이 측정 허용오차 `MEAS_EPS`를 참조하지 않는다.**

```
MEAS_EPS   = 버킷(0.1) + dashSpeed × dt = 0.165u
GATE_MARGIN = 0.300u
실효 여유   = 0.135u
```

`dashSpeed`가 24u/s를 넘으면 허용오차가 여유를 통째로 삼켜 **게이트가 뚫리는데도 PASS**가 된다.
Unity 이식 시 **`GATE_MARGIN`을 `MEAS_EPS`에서 유도하도록 고쳐라.**

| 6 | 벽슬라이드·벽점프 (지정 벽만) | 경계벽에서 안 붙는다 |
| 7 | **창대쉬** — 체공 0.2s + 8방향 0.15s | **변위 1.650u**, **4단 체인 4.536u ±0.05** |
| 8 | 맵 로더 — `temple-map.json` → 콜라이더 | 7층 74개 지오메트리 생성, `yOff` 정합 |
| 9 | 애니메이션 상태기 · run fps 유도 | 발이 미끄러지지 않는다 |
| 10 | 카메라 · 2배 · 클램프 | 시야 8.0×4.5u |
| 11 | FX 레이어 (`enabled` 토글 포함) | **on/off 양쪽에서 3~7단계 수치 동일** |
| 12 | 검증 19항목 포팅 + **역검증** | §9.3 변형이 전부 FAIL 재현 |

## 12. 최종 합격 기준

```
□ 도달 실측이 웹과 일치      점프 1.592 · 이단 2.886 · 대시 3.153 · 창대쉬 1.650 · 체인 4.536
□ 검증 19항목 통과
□ 역검증 — 일부러 망가뜨리면 FAIL이 재현된다
□ FX on/off 양쪽에서 이동 수치가 동일하다
□ 7층 전부 렌더 에러 0
□ 층 경계 밖으로 나갈 수 없다 (좌우 양방향)
```

**이 중 하나라도 안 되면 이식이 끝난 게 아니다.**

그리고 마지막 관문은 사람이다 — **오너가 직접 조작해 손맛을 판정**해야 완료다.
자동 검증은 "틀리지 않았다"를 보장할 뿐 "재미있다"를 보장하지 않는다.

`game-design.md` §6.9가 이걸 명시한다:

> **「이 영역은 개발자 본인의 손 튜닝이 최우선 — AI가 대신 못 하는 유일한 영역」**

감각 수치(체공 시간·돌진 속도·진동 세기·이펙트 길이)를 **AI 판단으로 확정하지 마라.**
인스펙터에 노출하고, 시작값은 이 문서 값으로 두고, **판정은 오너에게 넘겨라.**

# 맵 렌더링 이식 명세 — 그림 에셋 없이 같은 룩을 만든다

> **결론 먼저: 타일셋도 배경 이미지도 필요 없다.**
> 웹 프로토타입의 맵 비주얼은 **전부 그라디언트 + 축정렬 사각형 + 단순 다각형**이다.
> 외부 텍스처 0장, 블러 0회. Unity 셰이더 몇 개로 **같은 그림이 나온다.**
>
> 이게 이 프로젝트의 방침이기도 하다 — `game-design.md` §9.1:
> *"최종 화풍을 지금 정하지 않는다. 게임을 먼저 완성하고, 아트는 딱 한 번만 입힌다."*
> *"재미 검증은 **주스를 입힌 읽히는 도형** 상태에서 한다 — 주스 코드는 최종 아트에도 그대로 산다."*
>
> **최종 픽셀아트 화풍 확정은 데모 시점(§9.4 리트머스)의 결정이다. 지금이 아니다.**

## 3. 배경 — 4개 레이어

### 3.1 하늘 (전체 화면)

**고도에 따라 색이 변한다.** `alt = clamp(카메라 y / 월드 높이, 0, 1)` — 위로 올라갈수록 밝아진다.

```
세로 그라디언트 (0=화면 위, 1=화면 아래)
  0.00   lerp(skyTop,  #2b4b78, alt)
  0.45   lerp(skyMid,  #7fa4cc, alt)
  0.80   lerp(skyLow,  #dfe9f2, alt×0.9)
  1.00   lerp(#7a8ba3, skyHaze, alt×0.85)
```

**태양 광휘** — 화면 (0.80W, (0.16 − alt×0.05)H) 중심 방사형, 반지름 `max(W,H)×0.55`

```
0.00  rgba(255,246,214, 0.34 + alt×0.22)
0.28  rgba(255,226,168, 0.13 + alt×0.10)
1.00  rgba(255,220,160, 0)
```

### 3.2 원경 첨탑 (시차)

사각형 + 위에 얹힌 삼각형. 색 `rgba(122,146,178, 0.16 + depth×0.16)`.
시차: `x`는 카메라 x의 `0.008×depth`배, `y`는 카메라 y의 `0.9×depth`배로 따라간다.

### 3.3 구름 (시차)

소프트 원형 스프라이트. 시차 계수 `0.006×depth`(x) / `depth×7`(y).
`sin(t×0.00013 + 위상)×6px` 만큼 상하로 흔들린다.

> Unity에서는 **작은 소프트 원 스프라이트 3~4종**을 만들어 쓴다.

### 3.4 챔버(층 내부 배경)

층마다 하나. 세로 그라디언트 `#243147`(0) → `#192337`(0.42) → `#121a2b`(1).
아치 니치는 **도려내서 하늘이 비치게** 한다 (Unity에서는 스텐실 또는 알파 마스크).

> 원본은 층별로 오프스크린 캐시한다. Unity에서는 **층당 쿼드 1개**면 되므로 캐시가 불필요하다.

## 5. Unity 구현 권장안

### 5.1 지오메트리 — **셰이더 1개 + 쿼드 74개**

```
머티리얼 프로퍼티
  _Type      0=solid · 1=wall · 2=oneway
  _Size      (W, H) 월드 유닛      ← 이게 있어야 띠 두께를 u 기준으로 그린다
  _Finial    0/1
  _Time      맥동용
```

프래그먼트 셰이더에서 **로컬 UV로 띠·이음선·모서리를 전부 절차적으로** 그린다.
장점:
- 드로우콜 74개, 텍스처 0장
- 사각형 크기가 달라도 **띠 두께가 일정**하다 (9-slice로는 이게 안 된다)
- 팔레트를 셰이더 상수로 빼면 **색 튜닝이 한 곳**

> **대안(더 쉬움)**: 9-sliced 스프라이트. 다만 상단 캡 높이가 `min(H×0.42, 0.14u)`로
> **높이에 따라 변하므로** 얇은 발판에서 9-slice가 깨진다. 셰이더를 권한다.

### 5.2 배경 — 쿼드 6~8개

```
하늘 1 (전체화면, 셰이더 그라디언트 + 태양 방사)
첨탑 2~3 (시차, 스프라이트)
구름 1 (파티클 또는 스프라이트 풀)
챔버 1 (층당)
갓레이 1 (층당, 가산 메시)
비네트 1 (전체화면 오버레이)
```

### 5.3 정렬 순서

```
하늘 → 첨탑 → 구름 → 챔버 → 갓레이 → 지오메트리 → 캐릭터 → FX → 비네트 → HUD
```

⚠ 원본에서 **FX가 캐릭터보다 먼저 그려져 이펙트가 캐릭터 뒤에 가리는 버그**가 있었다.
FX는 캐릭터 **뒤/앞을 나눠서** 그린다 — 창대쉬 빛줄기는 캐릭터 **뒤**, 속도선은 **앞**.

### 5.4 픽셀 정합

```
카메라를 디바이스 픽셀 격자에 스냅 (반올림)  ← 도트 떨림 방지
Pixel Perfect Camera 사용, Upscale RT 끄고 Pixel Snapping 켜기
```

---

## 5.5 ★ FX(타격감) 레이어도 전부 이식된다

**이펙트에도 외부 텍스처가 사실상 없다.** 필요한 건 **소프트 원 1장뿐**이고 그것도 런타임 생성이 된다.

### 소프트 원 글로우 — 유일한 텍스처

원본은 색마다 **64×64 방사형 그라디언트**를 한 번 구워 캐시한다.

```
반지름 0.00 → 알파 1.00
       0.28 → 0.95
       0.58 → 0.38
       1.00 → 0.00
```

Unity에서는 **64×64 소프트 원 스프라이트 1장**을 만들고 **색은 `SpriteRenderer.color`로 틴트**한다.
색마다 텍스처를 만들 필요가 없다. `Texture2D`로 위 곡선을 그려 넣는 10줄이면 끝난다.

### 파티클 종류별 대응

| 종류 | 원본 | Unity |
|---|---|---|
| `dust` 먼지 | **각진 정사각형**. 한 변을 정수 픽셀로 스냅. 알파 `(1−u)²·a0` | 1×1 흰 쿼드 + 색. **크기를 정수 픽셀로 반올림** |
| `spark` 불똥 | 글로우 스프라이트. 반지름 `r·(1−0.4u)` | 소프트 원 + 가산 |
| `conv` 수렴 알갱이 | 글로우. **빨려들며 밝아진다** `alpha = min(1, 0.35+1.1u)` | 소프트 원 + 가산 |
| `flash` 섬광 | 글로우를 부챗살 축으로 **1.9 : 0.78 비등방 스케일** + 회전 | 소프트 원 + 비균등 스케일 + 회전 |
| `ring` 발광 도넛 | 방사형 그라디언트 도넛. 안쪽 0 → 중간 1 → 바깥 0. **두께가 반지름과 따로 논다** | **전용 셰이더**(반지름·두께 파라미터). 스프라이트 스케일로는 두께가 같이 늘어나서 안 됨 |
| `arc` 참격 | **18분할 절차적 폴리곤**. 두께가 `sin(π·s)`로 양 끝에서 가늘어짐. 크림+흰색 2겹 | **절차적 메시** (18세그먼트) |
| `beam` 창대쉬 빛줄기 | **렌즈형 폴리곤**. 가까운 끝이 길이의 20%에서 시작 | 절차적 메시 |
| `line` 대시 속도선 | 끝이 뾰족한 가늘고 긴 선 | 절차적 메시 또는 얇은 쿼드 |

⇒ **필요한 것: 소프트 원 텍스처 1장 + 셰이더 1개(ring) + 메시 빌더 1개(arc/beam/line).**

### ★ 2패스 렌더링 구조를 반드시 지킬 것

원본은 파티클마다 합성 모드를 바꾸지 않고 **「일반 합성 전부 → 가산 합성 전부」 2패스**로 그린다.
2배 배율이라 픽셀 채우는 양이 이미 4배여서 상태 전환 비용이 크기 때문이다.

Unity에서는 **머티리얼 2개**(일반 / 가산 `One One`)로 나누고 **정렬 순서로 묶어라.**
파티클마다 머티리얼을 바꾸면 배칭이 깨진다.

### ★ 캐릭터 앞뒤를 나눈다

원본 파티클에는 `L`(레이어) 필드가 있다. **창대쉬 빛줄기는 캐릭터 뒤**, **대시 속도선은 앞**이다.
전부 앞에 그리면 **0.15초 동안 캐릭터가 빛에 묻혀 자기 위치를 놓친다** — 실제로 났던 버그다.

### ★ 물리와 시간축을 분리한다

```
물리   고정 스텝 simDt = 1/120
이펙트 dtFx (상한 FX.dtMax)
```

**이펙트 시간을 물리 `dt`에 섞지 마라.** 히트스톱·슬로우를 물리에 걸면 이동 실측이 흔들려
검증이 통째로 무의미해진다. 원본이 이 이유로 히트스톱을 **포기**했다.

`FX.enabled = false`로 끄면 **이동 실측값이 한 글자도 안 변해야 한다.** 이게 이식 합격 조건이다.

### 파티클 예산

```
풀 상한       220개 (초과 시 오래된 것부터 폐기)
프레임당 생성 24개
실플레이 피크  38개  ← 4단 체인 연타 시
```

원본 실측: 이펙트 켜도 **프레임 시간 +0.0ms**(실플레이), 인위적 포화(220개 상시)에서 +4.7ms.
Unity에서는 더 여유롭다. **파티클 시스템 대신 단순 풀 + 배칭**을 권한다 —
모양이 전용(바늘선·초승달·렌즈)이라 Unity 기본 파티클 셰이프로는 안 나온다.

## 6. 이식하지 말 것

| | 이유 |
|---|---|
| `drawLabels` · `drawDebug` · `drawGrid` · `drawMinimap` | 에디터 뷰어 전용 |
| `drawReach` · `drawSpearPlan` | 설계 검증 오버레이 |
| `drawSpearFace` · `drawVault` | **창 꽂기·창대 도약은 폐기됐다** |
| 챔버 오프스크린 캐시 | Unity에서는 쿼드 1개라 불필요 |

## 7. 합격 기준

**웹 프로토타입 스크린샷과 나란히 놓고 비교한다.** 아래가 맞으면 성공이다.

```
□ 발판 상단에 대리석 캡 + 금 띠가 보인다
□ 벽에 세로 홈이 있고 위아래에 금 주두가 삐져나와 있다
□ 첨탑 캡이 뾰족한 금 삼각형이다 (= 못 서는 곳이라는 신호)
□ 원웨이 판 아래 노란 빛이 맥동한다
□ 위층으로 갈수록 하늘이 밝아진다
□ 갓레이 3줄기가 천장에서 내려온다
□ 원경 첨탑과 구름이 카메라보다 느리게 움직인다
```

**웹 원본**: https://abback-go.github.io/yemogame2/proto/index.html
`Enter` 플레이 · `L` 라벨 끄기 · `H` 도움말 끄기 → 그 상태가 비교 기준이다.
