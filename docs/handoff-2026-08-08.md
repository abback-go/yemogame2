## 2. 엔진 결정 — 현재 상태 (미확정)

- 목표: **전역 후 Unity 이식 → Steam 판매** (기본 노선)
- 고도(Godot) 검토 결과: 웹 에디터는 반쪽(성능·C# 불가), **안드로이드 앱은 의외로 본격적**(4.6 GABE로 온디바이스 빌드까지), 데스크톱이 본진.
- 확인된 사실: **고도로 만든 "할나급 도트 메트로바니아 플래그십"은 사실상 없다.** 할나·산나비·모모도라=Unity, Siege and the Sandfox=Unreal. 엔진 능력이 아니라 **생태계 성숙도** 문제.
- **C# 관련:** 고도의 C#은 데스크톱 전용(웹·안드로이드 불가). 그리고 언어가 같아도 엔진 API가 달라 코드는 안 넘어간다 — **C#의 이점은 "미리 배워둠"뿐.**
- ⇒ **결론: 엔진 선택은 나중에 해도 된다.** 지금 산출물(데이터·스펙·검증된 디자인)은 어느 엔진으로 가든 그대로 넘어간다.

## 3. 컨셉 (피벗 후) — 정본

**기획 정본:** [`docs/specs/2026-08-07-holy-spear-design.md`](specs/2026-08-07-holy-spear-design.md)

- **성창(聖槍) — 잊힌 성물** (가제). 2D 사이드뷰 도트 액션 **메트로바니아**
- **신전** = 주거지/수련처(구 마법학교 역할) · **인간계** = 탐험 무대
- **줄거리 축: 잊힌 성물 회수.** 성물을 되찾을 때마다 새 능력 해금 → 새 지역 개방 (**성물 = 능력 = 열쇠**)
- **신성력 = 창 강화 + 신성기 지원.** 적을 때릴수록 게이지가 차고, 창 강화로 터뜨리는 공격적 루프
- **유지:** 랭크 스탯 D~SSS(리테마) · 수업/스승 시스템 · juice 타격감
- **폐지:** 종족 · 전공/학과 → **단일 성창사 + 단일 스킬트리**

### ★ 시그니처: 창 꽂기 (Spear Anchor)

> **실물 창을 던져 벽·지형·적 표면에 박아 → 작은 발판이 생기고 → 딛고 도약 → 빠르게 회수(돌아오며 타격).
> 한 번에 하나만. 공중 부양 발판 없음(반드시 표면에 박혀야 함).**

- 포고 대신 채택. **이동·전투·수직 표현을 하나로 관통**하는 정체성
- 실물 창이라 던진 동안 무기가 없음 = **리스크·리워드 텐션**

### 물리 — 단일 진실원

`REACH`는 손으로 적지 않고 **`PHYS`에서 유도**합니다(물리를 튜닝하면 게이팅이 자동 재검증).

| 값 | 유도 결과 | 근거 |
|---|---|---|
| 단일점프 | **1.592u** | `jumpV²/2g`, `jumpV 9.10 / g 26.0` |
| 이단강림 | **2.886u** | `+ airJumpV²/2g`, `airJumpV 8.20` |
| 창대 도약 | **3.402u** | `vaultV²/2g`, `vaultV 13.30` |
| 대시점프 수평 | **3.153u** | `dashSpeed·dashTime + (체공−dashTime)·runSpeed·airControl` |
| 창 사거리 / 공격 위리치 | 5.0 / **0.80** | — |

> **창대 도약은 도약 나브 또는 박힌 창 위에서만 발동.**
> **게이트 갭은 이동기 한계 대비 최소 `0.30u` 초과**(프로젝트 규칙).

### 검증 11항목 (인게임 `T` / `node proto/verify-map.mjs`) — 전부 PASS

1. 충돌 타입 겹침 없음 2. 창 계획 유효(면·사거리) 3. 창 발판이 기존 지형에 안 파묻힘
4. **게이트 표면이 이동기만으로 도달 불가**(진입점 도달 폐포 + 기둥 차폐 판정)
5. **게이트 표적이 공격 리치 포함해도 도달 불가** 6. 게이트 갭 여유 ≥0.3u
7. 층간 포탈 양방향 정합 8. 체크포인트 참조 유효
9. **모든 층 클리어 가능**(가상 창 발판 탐색으로 출구 도달 증명) 10. 히든 수집물 도달 가능
11. **히든 게이트 성립**(전용 면 없이 불가 / 복귀 제약)

## 6. 어드바이저 검토 → v1.1에서 고친 것

v1.0 검토 결과 **72/100**. 핵심 지적: *"게이팅 검증 패널이 하드코딩이라 실제로는 아무것도 검증하지 않는다."*
그 사각지대에서 **시그니처를 건너뛰는 구멍 5건**이 데이터에 있었습니다.

| 층 | 문제 | 수정 |
|---|---|---|
| 5F | 성물 기둥 **상단에 올라타** 출구로 걸어감 | P-air2 삭제 · 기둥 상단 **첨탑캡(비착지)** · 코니스 2.4–2.6 |
| 5F | D-A2 게이트가 "발이 닿는가" 기준 — 창 리치 무시 | `(11.0,4.3)→(11.3,5.6)` · **공격 리치 반영** |
| 4F | *(어드바이저도 놓침)* P2→먼 기둥 머리→출구로 우회 | 기둥 머리 삭제, **첨탑캡** |
| 3F | 히든 창 발판이 목표보다 **멀어** 창이 장식 | **우벽 니치**(바닥+천장)로 **수직 게이트** 전환 |
| 7F | 테라스 `solid`가 진입 `oneway`를 덮음 → 6→7 전이 불능 | 테라스 `[0,4]`/`[6,16]` 분할 |
| 6F | 게이트 여유 **0.1u**(렛지스냅 0.08이면 사실상 0) | 착지단 재조정(L2 7.8/L4 14.3/L5 17.6/XE 19.6), HC를 **일방 포켓**으로 |

그 외: 창 발판 렌더가 **항상 왼쪽**으로 그려지던 버그(좌벽 창이 벽 안쪽으로 뻗음) 수정,
배지 겹침·비초점 라벨 디밍, 구름 스프라이트/챔버 오프스크린/비네트 캐시, DPR 상한 1.5.

> **검증기 역검증 완료:** 위 결함들을 코드에서 되돌리면 **전부 FAIL이 재현**됨 → 테스트가 공허하지 않음이 증명됨.
